# สมดุล combat (I5)

ผลจำลอง 1,000 ครั้งต่อช่องตาราง จาก `simulateFight` / `simulateMany` ใน `src/lib/combat/simulate.ts` ซึ่งเรียกโมดูลจริงของ combat (`armorClass`, `runAttacks`, `runEnemyAttacks`, `applyEnemyAttackOutcomes`, trait ของศัตรู I4, `applyAbilityActions` ของ class, `advanceEncounter`) ไม่ได้คัดลอกสูตรมาเขียนใหม่ ตารางแรก ("ผลก่อนจูน") คือผลจำลองรอบ I5 ก่อนแก้ค่า ส่วน "ผลหลังจูน" คือผลที่รันซ้ำหลังนำข้อเสนอมาใช้จริงในงาน I6 (ดูหัวข้อ "I6: ผลการจูนจริง" ท้ายไฟล์)

สร้างตารางใหม่ได้ด้วย (ไม่รันตอน `npm test` ปกติ, seed คงที่ ผลซ้ำได้):

```
SIM_REPORT=out.md npx vitest run src/lib/combat/simulate.report.test.ts
```

## เป้าหมาย

- การต่อสู้ปกติจบใน 3-5 รอบ
- บอสที่เลเวลเหมาะสมชนะ 70-85%

## สมมติฐานของการจำลอง

- ปาร์ตี้ 4 คน คนละ class (นักรบ, นักธนู, นักบวช, โจร) เลเวล 1 / 3 / 5 / 8 · XP ตามตารางเลเวล · HP = 20 + 5 x (เลเวล-1) · ค่า ability เริ่มต้นของ class + แต้มเพิ่มค่าที่เลเวล 4 และ 8 ลง ability หลัก (+2 ต่อครั้ง) · ไม่มีไอเท็มวิเศษ
- สองโปรไฟล์เกราะ: "ไม่มีเกราะ" (ชุดเริ่มต้นจริงของเกม ไม่มีเกราะ) และ "เกราะประจำ class" (นักรบ เกราะเหล็ก, นักบวช เกราะโซ่, นักธนู/โจร เกราะหนัง)
- ผู้เล่นทุกคนโจมตีศัตรูที่เหลือ pip น้อยที่สุด (เล็งโดยไม่มี advantage) ดาเมจ = ลูกเต๋าอาวุธ + โบนัสเลเวล ยกเว้นนักรบ/นักบวชที่ใช้ท่าประจำ class ในรอบนั้น (ยืนบังเพื่อนที่ HP น้อยสุด / อวยพรรักษาเพื่อนที่ขาด HP >= 5) ซึ่งใช้แทนการโจมตี นักธนู/โจรใช้ท่าทุกครั้งที่พร้อมและยังโจมตีด้วยดาเมจใหม่ · คูลดาวน์เดินตามจริง (`tickCooldowns`)
- ผู้เล่นลงมือก่อน ศัตรูที่ยังเหลือหลังรอบนั้นแต่ละตัวโจมตีผู้เล่นที่ยังไม่ล้มแบบสุ่ม 1 คน (บอส `boss_signature` โจมตี 2 คนทุกรอบที่ 3) ศัตรูที่ถูกกำจัดในรอบนั้นไม่โต้กลับ
- ไม่จำลอง potion, การหนี, death save, การฟื้น: คนที่ HP เป็น 0 ล้มค้างจนจบการต่อสู้ ("คนล้ม" = จำนวนคนที่ล้มตอนจบ) ไม่ใช่ตาย
- ต่อสู้ครั้งเดียวต่อรอบจำลอง เริ่มด้วย HP เต็มและคูลดาวน์ 0 ถ้ายังไม่จบใน 30 รอบนับเป็นแพ้
- "HP ปาร์ตี้ที่เหลือ" = ผลรวม HP ปัจจุบัน / ผลรวม HP สูงสุด ตอนจบ เฉลี่ยทุกครั้ง
- ชุดศัตรูมาตรฐาน: minion x4, normal x2, strong x1 + normal x1, boss x1 และชุด trait: normal x2 (pack, brute), boss x1 (armored, boss_signature)

## สรุปผลก่อนจูน

- การต่อสู้ **ง่ายเกินไปมาก**: ทุกชุดที่ไม่มี trait ชนะ 100% ที่ทุกเลเวล แม้บอสเลเวล 1 ชนะ 100% และเสียแค่ราว 10-14% ของ HP ปาร์ตี้ (เป้า 70-85%)
- การต่อสู้ปกติจบเร็วเกินไป: normal x2 ใช้ 1.2-1.7 รอบ, minion x4 / strong + normal ใช้ 2.2-2.9 รอบ (เป้า 3-5) บอสเปล่าใช้ 2.0-3.0 รอบ
- สาเหตุ: ปาร์ตี้ 4 คนโจมตีพร้อมกัน (ราว 3-4 pip ต่อรอบ) แต่ pip ของศัตรูน้อย (2 / 3 / 5 สำหรับ normal / strong / boss) และศัตรูตัวเดียวโจมตีได้ครั้งเดียวต่อรอบ ดาเมจ (เช่นบอสเฉลี่ย 9) เทียบกับ HP ปาร์ตี้ 80+ แทบไม่มีผล เกราะเปลี่ยนผลเล็กน้อยเพราะ AC ผู้เล่น 10-16 เทียบโบนัสศัตรู +3..+7
- เฉพาะบอสที่มีทั้ง `armored` + `boss_signature` ที่เลเวล 1 ถึงจะเริ่มมีความเสี่ยง (ชนะ 98.5% / ล้มเฉลี่ย 0.28 คน)

## ข้อเสนอจูน

**(นำไปใช้แล้วใน I6)** ได้ชุดนี้ซึ่งทำให้เข้าเป้าที่สุดโดยไม่เปลี่ยนโครงสร้างอื่น:

| ค่า | ปัจจุบัน | เสนอ | ไฟล์ |
|---|---|---|---|
| pip ต่อ tier (minion / normal / strong / boss) | 1 / 2 / 3 / 5 | 2 / 4 / 6 / 10 | `TIER_PIPS` ใน `src/lib/combat/encounter.ts` (ย้ายเข้า `constants.ts` แล้วใน I6; `normalizeEncounter` ตรวจ `maxPip` กับตารางนี้ และ UI อ่านจาก `maxPip` อยู่แล้ว) |
| โบนัสโจมตีศัตรู (minion / normal / strong / boss) | +3 / +4 / +5 / +7 | +3 / +5 / +6 / +9 | `ENEMY_ATTACK_BONUS` |
| ดาเมจ normal | 1d6+1 | 1d8+2 | `ENEMY_DAMAGE_DICE` |
| ดาเมจ strong | 2d4+2 | 2d6+3 | `ENEMY_DAMAGE_DICE` |
| ดาเมจ boss | 2d6+2 | 3d6+4 | `ENEMY_DAMAGE_DICE` |
| ดาเมจ minion, AC ศัตรู, ค่าคงที่ pip ของท่าผู้เล่น | คงเดิม | คงเดิม | - |

ผลที่ได้ (ตารางด้านล่าง): normal x2 ใช้ 2.2-3.1 รอบ, strong + normal 2.9-4.5 รอบ, minion x4 2.4-3.4 รอบ, บอสเปล่าเลเวล 1 ชนะ 89% เมื่อมีเกราะ (79.9% เมื่อไม่มีเกราะ, ใช้ 5.7 รอบ) เลเวล 3 ชนะ 99%, บอส `armored` + `boss_signature` เลเวล 1 ชนะ 49% / เลเวล 3 ชนะ 84% / เลเวล 5 ชนะ 99.8%

ข้อสังเกตเพิ่มเติม:
- ปาร์ตี้เลเวลสูงยังชนะง่ายแม้ใช้ตัวเลขชุดใหม่ (ศัตรูไม่โตตามเลเวล) การปรับความยากตามเลเวลต้องให้ AI เลือก tier / trait ที่หนักขึ้นตามเลเวลปาร์ตี้ (เช่น บอสเลเวล 5 ขึ้นไปควรมี trait 2 ตัว) แนะนำเพิ่มบรรทัดนี้ใน prompt ของ combat ถ้ายอมรับ
- บอสเปล่าเลเวล 1 ที่ 89% (มีเกราะ) สูงกว่าเป้า 70-85% เล็กน้อย แต่บอสที่มี trait อยู่ในช่วงต่ำกว่าเป้า (49% ที่ Lv1) ค่าเฉลี่ยของบอสทั้งสองแบบอยู่ราวเป้า ถ้าอยากให้บอสเปล่าเข้าเป้าเดี่ยวๆ ให้ขยับโบนัสโจมตีบอสเป็น +10
- ผู้เล่นเลเวล 1 (HP 20) อาจถูกบอสคริติคอลตาย: 6d6+4 เฉลี่ย 25 ในครั้งเดียว ควรรอผู้ใช้ตัดสินใจว่ารับได้ไหม (death save ยังช่วยได้)
- ข้อจำกัดของการจำลอง: ไม่มี potion/การหนี/death save/ไอเท็มวิเศษ และศัตรูเลือกเป้าสุ่ม ผลจริงอาจต่างเล็กน้อย

ค่าที่เปลี่ยน (อยู่ใน `src/lib/combat/constants.ts` ไฟล์เดียว ทุกที่อ้างจากที่นั่น): `TIER_PIPS` 1/2/3/5 → **2/4/6/10** (ย้ายมาจาก `encounter.ts`), `ENEMY_ATTACK_BONUS` +3/+4/+5/+7 → **+3/+5/+6/+9**, `ENEMY_DAMAGE_DICE` normal **1d8+2**, strong **2d6+3**, boss **3d6+4** (minion เดิม 1d4) ที่อื่นที่ปรับตาม: prompt ของ DM อ่านจำนวน pip จาก `TIER_PIPS` (ไม่ฮาร์ดโค้ดแล้ว), แถบ pip ใน `EncounterPanel` วาดได้ถึง 10 ช่อง (ช่องกว้างยืดหดตามจอ สูงสุด 28px ไม่ล้นบนจอแคบ) และเกณฑ์สี "แดง" เป็น pip ที่เหลือไม่เกิน 1/4 ของแถบ (บอส 10 pip แดงที่ 2, ศัตรู 4 pip แดงที่ 1 เหมือนเดิม) กติกา "บอสที่ pip เต็มเหลือไม่ต่ำกว่า 1 ในครั้งเดียว" ยังทำงานเหมือนเดิม (`maxPip` เท่ากับ pip เริ่มต้น)

### เทียบผลจำลองกับที่คาด (1,000 ครั้งต่อช่อง)

| ชุด | ที่คาด | ได้จริง | ต่าง |
|---|---|---|---|
| บอสเปล่า เลเวล 1 (เกราะประจำ class) | ≈ 89% | 89.0% | 0 |
| บอสเปล่า เลเวล 1 (ไม่มีเกราะ) | ≈ 80% | 79.9% | -0.1 |
| บอสเกราะหนา + ท่าไม้ตาย เลเวล 1 | ≈ 49% | 49.1% | +0.1 |
| บอสเกราะหนา + ท่าไม้ตาย เลเวล 3 | ≈ 84% | 84.2% | +0.2 |
| บอสเกราะหนา + ท่าไม้ตาย เลเวล 5 | ≈ 99.8% | 99.8% | 0 |

ไม่มีช่องไหนต่างเกิน ±5 จุด จึงไม่ต้องบันทึกใน pending.md และไม่ได้ปรับตัวเลขเอง

### ค่าที่ไม่ได้เปลี่ยน (ผลจำลองข้างบนใช้ค่าเดิมเหล่านี้) และข้อเสนอ

- `HIT_PIPS` = 1 และ `HEAVY_PIPS` = 2 คงเดิม: บอส 10 pip จากเต็มต้องใช้หมัดหนักอย่างน้อย 5 ครั้ง ไม่ตายเร็วเกินไป ผลจำลองยืนยัน (บอสเปล่าใช้ 3.3-5.7 รอบ) ไม่จำเป็นต้องปรับสัดส่วน
- `HURT_PIPS` ของแท็ก `[[enemy_hurt]]` และม้วนคัมภีร์ (Q1, ตัดสินใจ P18.3): คูณสองแล้ว ตอนนี้เบา/กลาง 2, หนัก 4 และม้วน 2/4/6 pip ตามความหายาก ผลสัมพัทธ์กลับเท่าก่อนจูน I6 (ม้วนเปลวไฟลดบอส 40%) ค่าอยู่ใน `src/lib/combat/constants.ts` ตัวจำลองไม่ได้ใช้ค่านี้ จึงไม่ต้องรันซ้ำ
- `REGEN_PIPS` ของศัตรู regenerating (1 pip ต่อ 2 รอบ) คงเดิม

### ความเสี่ยงที่ยังไม่แก้ (ผู้ใช้ยังไม่ได้ขอ)

1. ดาเมจบอส 3d6+4 เฉลี่ย 14.5 (คริติคอล 6d6+4 เฉลี่ย 25) ผู้เล่นเลเวล 1 (HP 20) อาจล้มในหมัดเดียว แม้ death save (H1) จะรองรับ
2. ศัตรูไม่โตตามเลเวลผู้เล่น: ปาร์ตี้เลเวลสูงยังชนะง่าย (บอสเปล่าเลเวล 5-8 ชนะ 100%) ควรให้ AI เลือกระดับและ trait หนักขึ้นตามเลเวลผู้เล่น

## Q2: ปรับระดับศัตรูตามเลเวลเฉลี่ยของทีม

ปัญหา: หลัง I6 บอสเปล่าเลเวล 5-8 ยังชนะ 100% เพราะศัตรูไม่โตตามเลเวล (ผู้เล่นได้ HP +5 ต่อเลเวล, โบนัสดาเมจ +1 ต่อ 2 เลเวล, proficiency, ability +2 ที่เลเวล 4 และ 8) ให้ server ปรับเอง ไม่พึ่ง AI

### สูตร (ไฟล์ `src/lib/combat/scaling.ts` ค่าคงที่ใน `constants.ts`)

- **เลเวลทีม L** = ค่าเฉลี่ยเลเวลของผู้เล่นที่ยังไม่ตาย (นับคนที่ล้ม) ปัดเศษ อย่างน้อย 1 (`teamLevel`) ถ้าตายหมดใช้ทุกคน
- **pip ตอนสร้างศัตรู**: `pip = base + round(base x (L-1) x 35%)` (`ENEMY_LEVEL_PIP_PERCENT = 35`) เช่น บอสเลเวล 1/3/5/8 = 10 / 17 / 24 / 35 pip, normal = 4 / 7 / 10 / 14 เก็บเป็น `maxPip` ใน encounter (`applyEnemyTags(..., level)`; `normalizeEncounter` ยอมรับ `maxPip` ตั้งแต่ค่าฐานถึงค่าของเลเวล 10) กติกา "บอสที่ pip เต็มเหลือไม่ต่ำกว่า 1" ยังใช้ได้ เลเวลที่ใช้คือเลเวลตอนศัตรูปรากฏ ไม่ปรับย้อนหลังระหว่างต่อสู้
- **โบนัสโจมตี**: `+ floor((L-1) / 3)` (`ENEMY_LEVEL_ATTACK_EVERY = 3`) ทุก tier คำนวณตอนศัตรูโจมตีจากเลเวลทีมขณะนั้น
- **ดาเมจ**: `+ floor((L-1) / 1)` ค่าคงที่ต่อโดน (`ENEMY_LEVEL_DAMAGE_EVERY = 1`) ไม่ถูกคูณสองตอนคริติคอล (เหมือนโบนัสคงที่เดิม) รวมกับ brute ได้
- เลเวล 1 ได้ค่าเท่า I6 ทุกตัว (ไม่มีโบนัสเพิ่ม) จึงไม่จำกัดดาเมจบอสสำหรับเลเวลต่ำเพิ่ม (P18.1 คงไว้) AC ศัตรูและ HIT_PIPS / HEAVY_PIPS ไม่เปลี่ยน

### เหตุผล

- pip เป็นคันโยกหลัก: บอสเลเวลสูงตายใน 3 รอบเพราะปาร์ตี้ 4 คนตีรวมกัน 4+ pip ต่อรอบ การเพิ่มแค่โบนัสโจมตี/ดาเมจ (ลอง +1 ต่อ 2 เลเวล ถึง +1 ต่อเลเวล) ไม่พอ บอสเลเวล 8 ยังชนะ 98-99% เพราะบอสตายก่อนที่จะโจมตีได้ครบหลายครั้ง ส่วน pip +35% ต่อเลเวลทำให้การต่อสู้ยาวขึ้น ศัตรูมีเวลาโจมตีมากขึ้น
- โบนัสโจมตีแบบช้า (ทุก 3 เลเวล) เพราะ AC ของผู้เล่นแทบไม่โต (ไม่มีโบนัสต่อเลเวล) ถ้าโต +1 ต่อเลเวลจะโดนเกือบทุกครั้งแล้วผู้เล่นเลเวลสูงที่ไม่มีเกราะรับไม่ไหว ดาเมจแบบคงที่ +1 ต่อเลเวลทำให้ศัตรูไล่ตาม HP ผู้เล่น (+5 ต่อเลเวล) ทัน
- สแกนค่า (attack ทุกกี่เลเวล / damage ทุกกี่เลเวล / pip %) หลายชุด เลือกชุด 3 / 1 / 35 ที่ชนะอยู่ในช่วงใกล้เป้าที่สุดสำหรับบอสเปล่าทุกเลเวล

### ผลจำลองหลัง Q2 (1,000 ครั้งต่อช่อง ใช้ `simulateFight` ที่ส่งเลเวลทีมให้ศัตรูเหมือนใน server)

บอสเปล่า (boss x1) ชนะ % เทียบเป้า 70-85%:

| เลเวล | ก่อน Q2 (เกราะ class) | หลัง Q2 ไม่มีเกราะ | หลัง Q2 เกราะ class | หลัง Q2 รอบเฉลี่ย (เกราะ class) |
|---|---|---|---|---|

| 5 | 100.0 | 83.7 | 91.2 | 8.75 |

ชุดอื่น (เกราะ class): normal x2 ชนะ 100% ทุกเลเวล (3.1 / 4.6 / 5.0 / 6.2 รอบ) · strong + normal ชนะ 99.5-99.9% (4.5 / 6.6 / 7.0 / 8.8 รอบ) · minion x4 ชนะ 100% (3.4 / 4.6 / 5.5 / 6.7 รอบ) · บอส armored + boss_signature ชนะ 49% / 20% / 39% / 21% ที่เลเวล 1 / 3 / 5 / 8

### เทียบกับเป้า และสิ่งที่ต่างมาก (ไม่ได้ปรับเกินสูตร)

- บอสเปล่า: เข้าเป้า 70-85% ในส่วนใหญ่ ช่องที่หลุด: เลเวล 3 ไม่มีเกราะ 59% (ต่ำกว่า 11 จุด), เลเวล 5 เกราะ class 91% (สูงกว่า 6 จุด), เลเวล 1 เกราะ class 89% (ค่าเดิมของ I6 ไม่แตะ) เลเวล 4 และ 8 ได้ ability +2 จึงทำให้ผลไม่เรียบ
- **บอสที่มี trait armored + boss_signature ยากเกินเป้ามาก** (เลเวล 3-8 ชนะ 9-39% ไม่มีเกราะ/เกราะ class) เพราะ trait บวก AC และโจมตี 2 คน ซ้อนกับ pip/ดาเมจที่โตตามเลเวล ไม่ได้ปรับเกินสูตร ควรให้ผู้ใช้ตัดสินใจว่า (ก) ยอมรับว่าบอสพิเศษยากกว่าบอสเปล่าหนึ่งขั้น (ข) ให้ prompt จำกัดบอสไว้ trait เดียวเมื่อเลเวลต่ำ หรือ (ค) ลด `ENEMY_LEVEL_PIP_PERCENT` ลง
- การต่อสู้ทั่วไป (normal / strong / minion) ชนะเกือบ 100% แต่ยาวขึ้นเป็น 4.6-8.8 รอบที่เลเวล 3-8 (เป้า 3-5) เพราะ pip ที่โตทุกระดับ ไม่ได้แยกสูตรตาม tier ถ้าเกินไปสำหรับ minion ควรใช้ค่า % ต่ำลงเฉพาะ tier เล็ก
- การจำลองไม่รวม potion, death save, ไอเท็มวิเศษ และ "ปาร์ตี้เลเวลสูงที่แต่ละคนมีเกราะดีกว่านี้" ผลจริงอาจต่างเล็กน้อย
