# ร่างกลไกไอเท็มวิเศษใหม่ (F5i)

สถานะ: **ร่างให้ผู้ใช้เลือก ยังไม่ได้ใส่ในโค้ด** เมื่อเลือกแล้ว งาน F5j จะแตกเป็น task ย่อยต่อกลไก ตัวเลขทั้งหมดเป็นค่าเริ่มต้นที่ผมเสนอ ยังไม่เคยลองเล่นจริง

## เป้าหมาย

ตอนนี้ไอเท็มวิเศษ 100 ชิ้น (งาน F5b) มีกลไกได้แค่ 6 แบบ ต่างกันที่ชื่อ ตัวเลข และ skill ผู้ใช้ต้องการไม่ให้ระบบซ้ำซาก จึงเสนอ "กลไกพิเศษ" ที่ไอเท็มระดับหายากและตำนานแต่ละชิ้นแบกได้ 1 อย่าง นอกเหนือจากตัวเลขพื้นฐาน เช่น ดาบ +2 ที่เมื่อทอย nat 20 หัก pip เพิ่ม ไอเท็มระดับ "ไม่ธรรมดา" ยังมีแค่ตัวเลขพื้นฐาน เพื่อให้ของชั้นสูงรู้สึกต่างจริง

## ระบบที่กลไกพวกนี้ไปต่อกับ (อ่านจากโค้ด)

- รอบหนึ่งเดินตามลำดับใน `src/lib/round/processRound.ts`: ใช้ยา → ความสามารถ class → AI วางแผนเช็ก/โจมตี → server ทอยและตัดสิน (`src/lib/character/checkPlan.ts`, `src/lib/combat/attack.ts`) → AI เล่าเรื่อง → ใช้ tag (`hurt`/`heal`/`gold`/`xp`/ศัตรู) → บันทึก
- ดาเมจที่ผู้เล่นโดนมี 2 ทาง และทั้งสองทางหักค่า `armorReduction` อยู่แล้ว: ทาง server (`enemy_attack` ใน `src/lib/combat/attack.ts` บรรทัด 132) และทางที่ AI สั่งผ่าน tag `hurt` (`src/lib/character/applyTags.ts` บรรทัด 61 และ 69) กลไกป้องกันต้องต่อให้ครบทั้งสองทาง
- ผู้เล่นถือได้ 3 ช่อง: อาวุธ, เกราะ, เครื่องประดับ (ช่องหลังจากงาน F5d) กลไกจึงผูกกับชนิดไอเท็มได้ตามตารางด้านล่าง

## ข้อควรระวังด้านบาลานซ์และความเสี่ยง

- **X1, X3 ต่อบอส:** บอสมี 5 pip และต้องไม่ตายในการโจมตีเดียวตามกติกาเดิม ถ้ามีหลายคนสวม X1/X3 พร้อมกันการต่อสู้จะสั้นลงมาก ตั้งเพดาน: สวมกลไกชนิดเดียวกันซ้ำกันไม่ได้ (นับครั้งเดียวต่อผู้เล่น)
- **X4, X12 กับดาเมจทางที่ AI สั่ง:** ดาเมจจาก tag `hurt` ที่ AI ใส่เองไม่ผ่าน `enemy_attack` ต้องหักทั้งสองทางไม่งั้นผู้เล่นได้ผลไม่สม่ำเสมอ และต้องเขียนเทสต์ทั้งสองทาง
- **X5 ฟื้นเมื่อชนะ:** ถ้า AI เปิดการต่อสู้กับศัตรู 1 ตัวซ้ำๆ จะฟาร์มการฟื้น HP ได้ จึงจำกัดครั้งเดียวต่อการต่อสู้และต้องมีศัตรูอย่างน้อย 2 ตัวหรือมีบอสจึงนับ
- **X7 ถุงเงินโชคดี:** ราคาไอเท็มวิเศษอยู่ที่ 70–160 ทอง และทองต่อรางวัลเฉลี่ย 7 / 15.5 / 31 +2 ต่อครั้งเพิ่มได้ราว 6–30% ถ้าห้องสะสมทองเร็วเกินให้ลดเป็น +1
- **X12 กับโหมดตายจริง (งาน H1–H3):** ต้องตกลงว่า "ไม่ยอมล้ม" ป้องกันการล้มที่ 0 HP ซึ่งยังไม่ใช่การตายจาก death save ล้มเหลว 3 ครั้ง ควรทำหลัง H1
- ทุกกลไกต้องแสดงในหน้ากระเป๋าให้ผู้เล่นรู้ว่าสวมแล้วได้อะไร (งาน F5h)

## วิธีนำไปใช้กับไอเท็ม 100 ชิ้น

- เพิ่มฟิลด์ `effects` (รายการกลไก 0–1 อย่าง) ในข้อมูล `src/lib/inventory/magicItems.ts` ของงาน F5b
- ไม่ธรรมดา: ไม่มีกลไกพิเศษ · หายาก: มี 1 กลไกขนาดเล็ก (เช่น X3, X7, X8) · ตำนาน: มี 1 กลไกหลัก (เช่น X1, X4, X9, X12)
- กลไกกลุ่มเล็กและไม่ต้องเก็บข้อมูลเพิ่ม (X1, X2, X3, X7, X8) ใส่ได้ก่อน ส่วน X4, X5, X6, X9 ต้องแก้หลายจุดแต่ไม่แตะ DB ส่วน X10–X12 แตะ DB และควรทำทีหลัง

## ชุดที่ผมแนะนำ

1. **รอบแรก (ไม่แตะ DB):** X1, X2, X3, X4, X7, X8 ให้ไอเท็มหายาก/ตำนานแตกต่างกันชัดเจนด้วยต้นทุนต่ำ
2. **รอบสอง:** X5, X6, X9 (ชุดธีม ทำให้ 100 ชิ้นไม่ซ้ำซากเพราะมีเหตุผลให้สะสม)
3. **รอบสาม (ทำหลัง H1):** X10, X11, X12

## เมื่อผู้ใช้เลือกแล้ว

ผมจะแตกงาน F5j เป็น task ย่อยต่อกลไก เรียงตามความยาก เริ่มจากกลไกเล็ก แต่ละ task: เพิ่มกลไกในโค้ดพร้อมเทสต์ทั้งสองทางดาเมจ (ถ้าเกี่ยว) → เพิ่มฟิลด์ `effects` ในไอเท็มที่ใช้ → แสดงผลในหน้ากระเป๋า
