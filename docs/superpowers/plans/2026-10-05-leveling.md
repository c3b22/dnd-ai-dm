# Leveling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Characters earn party-wide XP from AI tags, derive a level (max 10) from stored `xp`, and gain max HP and weapon damage per level.

**Architecture:** One new column `players.xp`. A pure module `src/lib/character/leveling.ts` owns every level number and the XP-tag application. `players.max_hp` becomes the *base* max HP; effective max HP (`max_hp` + level bonus) is computed once at load (server repository and client fetch) and the bonus is subtracted again before saving. The AI only emits `[[xp: tier]]` / `[[milestone]]`; the server decides amounts.

**Tech Stack:** TypeScript, Next.js, Supabase (Postgres RPC `apply_changes`), Vitest (`npx vitest run <file>`).

**Spec:** `docs/superpowers/specs/2026-10-05-leveling-design.md`

## Global Constraints

- Max level **10**; cumulative XP per level: 0, 60, 150, 270, 420, 600, 810, 1050, 1320, 1620.
- Max HP bonus **+5 per level above 1** (level 10 = +45). Damage bonus **`floor((level − 1) / 2)`** (L3 +1, L5 +2, L7 +3, L9 +4; L10 = +4). Damage bonus applies to player weapon damage only, never healing.
- XP per tag: `small` 10, `medium` 25, `large` 50, `[[milestone]]` 100. Recipients: every player whose status is `active` in the round's final state.
- At most **one `xp` tag and one `milestone` tag count per round**; at most **one level gained per player per round**.
- On level-up, current `hp` rises by the max-HP bonus gained (+5), not a full heal.
- `players.max_hp` = base max HP (excludes level bonus). Existing revive/wipe/sanctuary rules and `MIN_MAX_HP = 10` stay, applied to the base part.
- Never tell the AI XP numbers or thresholds; show it only each player's level.
- Do **not** run `npm run build` or delete `.next` (the user's `npm run dev` shares it). Verify with `npx vitest run` and `npx tsc --noEmit`.
- Tests sit next to their source file, Vitest style (`describe`/`it`/`expect`), as in `src/lib/character/applyTags.test.ts`.

## Review Focus

- XP awarded that crosses two thresholds at once → player gains exactly one level and keeps surplus (below the next threshold); never silently drops to the wrong level. (Task 1, 3)
- A downed player in the same round as an XP tag gets nothing; a player revived by a tag in the same round does get it. (Task 3)
- Sanctuary / revive / wipe for a leveled player never produces `maxHp` below `MIN_MAX_HP + bonus` and sanctuary lands on `BASE_MAX_HP + bonus`. (Task 3)
- A character from older data/tests with no `xp` behaves as level 1. (Task 1, 3)
- `[[xp: HUGE]]`, `[[XP: Small]]`, a second `[[xp: large]]` in one narration: bad tag hidden and ignored, casing accepted, extra tag dropped. (Task 2, 3)
- Stale retry after tags were applied must not add XP again; saved base `max_hp` must not drift upward after a level-up. (Task 4, 5)

## File Structure

- Create `src/lib/character/leveling.ts` (+ test): all level math and `applyXpTags`.
- Modify `src/lib/character/constants.ts`: level constants. `types.ts`: `Character.xp?`. `tags.ts`: new tags. `applyTags.ts`: base/bonus-aware sanctuary/revive/wipe. `prompt.ts`: level display and tag docs.
- Create `supabase/migrations/0013_xp.sql`: `xp` column and `apply_changes` extension.
- Modify `src/lib/round/roundRepository.ts`: load effective max HP + xp, save base max HP + xp. `processRound.ts`: damage bonus and XP step.
- Modify `src/lib/supabase/players.ts`, `src/components/HpBar.tsx`, `src/components/PlayerOrder.tsx` (+ the stylesheet that defines `.hp-track`): level badge and XP bar.

Spec deviation: `Character` gets only `xp?` (level is always derived with `levelForXp`), not a separate `level` field, so the two can never disagree.

### Task 3: Applying XP; base/bonus-aware sanctuary, revive and wipe

**Files:**
- Modify: `src/lib/character/leveling.ts`, `src/lib/character/applyTags.ts`
- Test: `src/lib/character/leveling.test.ts`, `src/lib/character/applyTags.test.ts`

**Interfaces:**
- Consumes: Task 1 functions, Task 2 tags, `Character`, `CharacterTag`.
- Produces: `applyXpTags(characters: Character[], tags: CharacterTag[]): { characters: Character[]; changes: string[] }` in `leveling.ts` — does not mutate input; ignores everything but `xp`/`milestone`.

Behaviour of `applyXpTags` (decisions the signature does not carry):
- Gain = value of the **first** `xp` tag plus the **first** `milestone` tag in `tags`; later ones are ignored. No such tags → input unchanged, no changes.
- Only players with `status === 'active'` receive XP.
- New XP is capped so a player gains at most one level: if `level < MAX_LEVEL`, `newXp = Math.min(xp + gain, LEVEL_XP_THRESHOLDS[level + 1] - 1)` (index `level + 1` is the XP for level `level + 2`); at max level no cap. If the level rose, `maxHp += HP_PER_LEVEL` and `hp += HP_PER_LEVEL`.
- `changes` Thai lines: one `ทุกคนได้ +N XP` line (N = total gain), then per level-up `<name> ขึ้นเลเวล <L> (max HP +5, ดาเมจ +<bonus gained, omit if 0>)`.

Changes to `applyCharacterTags` (bonus = `levelHpBonus(levelForXp(c.xp ?? 0))`, per character):
- sanctuary: `c.maxHp = BASE_MAX_HP + bonus`.
- revive and wipe: floor is `MIN_MAX_HP + bonus` instead of `MIN_MAX_HP`.

- [ ] **Step 1: Write failing tests** in `leveling.test.ts` (`applyXpTags`, using a local `char()` helper like `applyTags.test.ts`):
  - `xp: small` on `{xp: 0}` → xp 10, change line `ทุกคนได้ +10 XP`.
  - Two `xp` tags + one `milestone` → only first xp + milestone counted (e.g. small then large + milestone = 110).
  - `{xp: 50, hp: 15, maxHp: 20}` + `milestone` (would reach 150 = level 3) → capped to one level: xp **149**, level 2, `maxHp` 25, `hp` 20, and a line containing `ขึ้นเลเวล 2`; a following call with `xp: small` on that result reaches 159 → level 3, `maxHp` 30.
  - Downed player gets no XP and no hp change; active players in the same call do.
  - Character without `xp` field is treated as 0; level 10 player's `maxHp`/`hp` unchanged and xp keeps growing.
  - Input array/objects not mutated.
  In `applyTags.test.ts`:
  - Sanctuary with `{xp: 150, maxHp: 22}` (level 3, base 12) → `maxHp` 30.
  - Revive with `{xp: 150, maxHp: 30, revivesSinceSanctuary: 5}` → `maxHp` not below 20; hp = `REVIVE_HP`.
  - Whole-party wipe with leveled players → every `maxHp >= 10 + bonus`, hp = ceil(maxHp / 2).
  - Existing cases without `xp` still pass unchanged.
