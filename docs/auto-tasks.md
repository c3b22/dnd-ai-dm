# Auto Tasks

แตกจาก [feature-backlog.md](feature-backlog.md) เป็นงานย่อยสำหรับสั่งทำอัตโนมัติ ทำทีละ task ตามลำดับ ข้าม task ที่ติด `BLOCKED` ไปจนกว่าผู้ใช้จะปลดให้

สถานะ: `[ ]` พร้อมทำ · `[!]` BLOCKED (ต้องรอผู้ใช้ตัดสินใจ ห้ามหยิบมาทำเอง) **งานที่ทำเสร็จแล้วให้ลบออกจากไฟล์นี้** (ไม่ติ๊ก `[x]` ค้างไว้) ประวัติของงานดูได้จาก `git log` ของ branch และ commit ของแต่ละ task

## กติกาที่ใช้กับทุก task

- **Test-first** (Vitest + Testing Library) ตาม pattern เดิม: inject Supabase client, ไฟล์ `*.test.ts` อยู่ข้างไฟล์จริง
- **1 task = 1 commit** บน branch แยก (ไม่ push, ไม่เปิด PR เอง) รัน `npm test` ผ่านทั้งหมดก่อน commit
- **ห้ามรัน `npm run build` และห้ามลบ `.next`** ผู้ใช้เปิด `npm run dev` ค้างไว้ ใช้ร่วม `.next` ถ้าพังเซิร์ฟเวอร์ผู้ใช้ล่ม ตรวจชนิดด้วย `npx tsc --noEmit` แทน
- **Migration: เขียนไฟล์ `.sql` ใน `supabase/migrations/` เท่านั้น ไม่รันกับ Supabase จริง** ใช้เลขถัดไปที่ว่าง (ล่าสุดคือ `0015` ซึ่งมีซ้ำ 2 ไฟล์ อย่าไปแก้/เปลี่ยนชื่อ) โค้ดที่พึ่ง column ใหม่ต้องทนได้ถ้า column ยังไม่มีใน production (best effort แบบเดียวกับ `current_scene_id` ใน `createCampaign.ts`)
- API route ใช้ pattern Bearer token เดียวกับ `src/app/api/adventures/route.ts` (`createServiceRoleClient` + `auth.getUser(token)`)
- ข้อความ UI เป็นภาษาไทย ตามของเดิม
- **เรื่องที่ต้องให้ผู้ใช้ตัดสินใจ หรืองานที่ทำค้าง ให้บันทึกใน [pending.md](pending.md) เป็นภาษาไทยเท่านั้น** แล้วข้าม task นั้นไปทำข้ออื่นต่อ ห้ามหยุดถามกลางคัน ห้ามเดาเอง เมื่อทำ task เสร็จให้ลบ task นั้นออกจากไฟล์นี้ (พร้อมบรรทัดย่อยของมัน) และอัปเดตตารางสถานะใน pending.md
- "เจ้าของห้อง" = ผู้เล่นที่ `joinedAt` เก่าสุด (`findOwnerId` ใน `src/lib/campaign/turnOrder.ts`) ไม่มี `owner_id` บนตาราง campaigns

## สมมติฐานที่ผู้ใช้ยืนยันแล้ว

- ลบห้องระหว่างรอบสถานะ `processing` → ตอบ 409 ให้ลองใหม่ ไม่ลบกลางประมวลผล
- import เนื้อเรื่องที่แชร์มา: คัดลอกรูปฉากไป storage ของสำเนาแบบ best effort (คัดลอกไม่ได้ = `imagePath` เป็น null) อนุญาต import ซ้ำได้ (ไม่ dedupe) แต่ห้าม import เนื้อเรื่องของตัวเอง
- share code ยาว 8 ตัว ยกเลิกการแชร์ได้ (ตั้งเป็น null แล้วลิงก์ตาย) สำเนาที่ import ไปแล้วไม่ได้รับผลกระทบ
- ความทรงจำโลกเกมใช้ 3 ชนิด `npc` / `quest` / `clue`

## I. Combat แบบ AC (แทนการตัดสินใจ P3 เดิม)

- [x] **I6 จูนสมดุล combat ตามผลจำลอง I5** (auto/tasks 2674b0d) — ตัดสินใจแล้ว (P13): ผู้ใช้เลือก**ใช้ข้อเสนอทั้งหมด** ปัจจุบัน combat ง่ายเกินไป (ปาร์ตี้ชนะราว 100% แทบทุกชุด จบใน 1.2–3 รอบ เป้า 3–5 บอสเปล่าเลเวล 1 ชนะราว 100% เป้า 70–85%) ตัวเลขที่ต้องเปลี่ยน:
  - pip ต่อระดับศัตรู (minion / normal / strong / boss): 1/2/3/5 → **2/4/6/10** (`TIER_PIPS` ตอนนี้อยู่ใน `src/lib/combat/encounter.ts` ให้ย้ายเข้า `src/lib/combat/constants.ts` ไฟล์ค่าคงที่ไฟล์เดียวและให้ทุกที่อ้างจากที่นั่น)
  - `ENEMY_ATTACK_BONUS`: +3/+4/+5/+7 → **+3/+5/+6/+9**
  - `ENEMY_DAMAGE_DICE`: normal **1d8+2**, strong **2d6+3**, boss **3d6+4** (minion เดิม)
  - ต้องตรวจทุกที่ที่ฝังค่า pip เดิมไว้: prompt ของ AI (`encounter` ใน `assemblePrompt.ts` และคำอธิบายแท็ก `[[enemy]]`), UI แผงศัตรู (`EncounterPanel`: ตัดช่องแถบ pip ถึง 10 ช่องให้พอดีและยังอ่านง่ายบนจอแคบ), กติกา "บอสที่ pip เต็มถูกตีให้เหลือไม่ต่ำกว่า 1 ในครั้งเดียว", เกณฑ์ pip ของหมัดหนัก (`HEAVY_PIPS`/`HIT_PIPS` อาจต้องปรับสัดส่วนให้บอส 10 pip ยังไม่ตายเร็วเกินไป ถ้าจำเป็นให้เสนอค่าแต่อย่าเปลี่ยนเองโดยไม่ระบุในผลสรุป) และเทสต์ทั้งหมดที่ฮาร์ดโค้ดค่าเดิม (`encounter.test.ts`, `attack.test.ts`, `processRound.test.ts`, เทสต์ของ simulateFight/simulateMany)
  - ทำซ้ำการจำลอง I5 (`simulateMany`, 1,000 ครั้งต่อช่อง) หลังแก้ แล้วบันทึกผลใน `docs/combat-balance.md` เทียบกับผลที่คาดจากข้อเสนอ: บอสเปล่าเลเวล 1 ชนะ ≈ 89% (ไม่มีเกราะ ≈ 80%), บอสเกราะหนา + ทักษะเฉพาะ เลเวล 1 / 3 / 5 ≈ 49% / 84% / 99.8% ถ้าผลต่างจากที่คาดมาก (เกิน ±5 จุด) ให้บันทึกไว้ใน `pending.md` ไม่ต้องปรับตัวเลขเอง
  - **ความเสี่ยงที่ต้องบันทึกในผลสรุป ไม่ต้องแก้ในงานนี้:** ดาเมจบอส 3d6+4 เฉลี่ย 14.5 (คริติคอลราว 25) ผู้เล่นเลเวล 1 (HP 20) อาจล้มในหมัดเดียว แม้มี death save (H1) รองรับ และศัตรูไม่โตตามเลเวล (ควรให้ AI เลือกระดับและ trait หนักขึ้นตามเลเวลผู้เล่น) ผู้ใช้ยังไม่ได้ขอแก้สองข้อนี้ จึงให้แค่บันทึก
  - ขึ้นกับ: I5 (เสร็จแล้ว)
